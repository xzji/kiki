# 任务执行情况入口与执行监控侧栏落地方案

## Summary

将 `docs/draft/task-execution-monitor-demo.html` 中设计的「任务执行情况」入口与右侧监控侧栏落地到真实项目。落地内容包括：

1. 在收件箱页（`src/app/page.tsx`）日期标题右侧新增「任务执行情况」入口按钮（带实时执行中数量徽标）。
2. 新增一个**可拖拽宽度**的执行监控侧栏组件 `TaskMonitorDrawer`，按 `待执行 / 执行中 / 已暂停 / 已完成` 四个板块分组展示**聚合全部 Goal 的任务实例**，空板块不展示，每板块支持折叠/展开。
3. 侧栏顶部提供并发上限（`maxConcurrentTasks`）的步进器与占用进度条；每个任务卡片提供 开始 / 暂停 / 继续 / 停止 / 重新执行 操作，**接入真实后端逻辑**（`runTaskExecutionAction` + `cancelGoalInstance` + `easterEggSettingsStore`）。
4. 点击任务卡片**复用现有的 `TaskDetailDrawer`**（不新开发详情组件），通过现有 `useTaskDrawerStore.open(goalId, taskId)` 打开。布局为：详情栏贴屏幕最右（60vw），监控栏在其左侧。
5. 收起联动：先收详情栏 → 监控栏滑回最右；直接收监控栏 → 详情栏一并收起。

## Proposed Changes

### 1. 新建监控状态 store：`src/stores/taskMonitorStore.ts`

**为什么**：监控栏的开关、折叠状态、宽度需要跨组件（入口按钮在 page、抽屉在 AppShell）共享，且与 `taskDrawerStore`（详情）解耦。

**做什么**：新建 zustand store：
```ts
type TaskMonitorStore = {
  open: boolean;
  width: number;            // 默认 400，可拖拽，clamp [320, 640]
  collapsedSections: Record<string, boolean>; // key: queued/running/paused/done
  openMonitor: () => void;
  closeMonitor: () => void;
  setWidth: (w: number) => void;
  toggleSection: (key: string) => void;
};
```
- `closeMonitor` 仅置 `open=false`；详情栏的联动收起在抽屉组件里通过 effect 处理（见第 4 点）。
- `width` 用 `persist` 持久化（参考 `easterEggSettingsStore` 的 persist 写法），key `kiki.task-monitor`。

### 2. 派生选择器：`src/lib/taskMonitor.ts`（新建）

**为什么**：将「聚合全部 Goal 的任务实例 + 按 status 分组」的逻辑集中，便于入口徽标与抽屉复用。

**做什么**：导出纯函数：
```ts
export type MonitorRow = {
  goalId: string; taskId: string; instanceId: string;
  taskTitle: string; goalTitle: string;
  taskType: Task["taskType"]; triggerRule: string;
  status: TaskInstanceStatus;
  group: "queued" | "running" | "paused" | "done";
  result?: "ok" | "fail";        // done 时区分 completed / error
  createdAt: string;
};
export function selectMonitorRows(goals: Goal[]): MonitorRow[];
export function groupMonitorRows(rows): Record<group, MonitorRow[]>;
```
分组映射（已确认）：
- `running` ← `in_progress`
- `queued` ← `pending`
- `paused` ← `paused` 或 `awaiting_user`
- `done` ← `completed`（result=ok）/ `error`（result=fail）

每个 Task 遍历其 `instances`，每个 instance 产出一行。`done` 板块即「全部历史执行记录」。

### 3. 入口按钮：改 `src/app/page.tsx`

**为什么**：用户要求入口在收件箱页。

**做什么**：将现有 `<h1>` 改为 flex 行，右侧加按钮：
- 文案「任务执行情况」+ 实时执行中数量徽标（来自 `selectMonitorRows` 中 `group==="running"` 计数）。
- 样式遵循 design-system 次级按钮：`rounded-lg border border-[#E5E7EB] hover:border-[#111]`，徽标用绿色胶囊 `bg-[#E6F4EA] text-[#137333]`。
- 点击调用 `useTaskMonitorStore.getState().openMonitor()`。
- 数量为 0 时不显示徽标。

### 4. 监控抽屉组件：`src/components/task/TaskMonitorDrawer.tsx`（新建）

**为什么**：核心 UI；从 demo 的 HTML/JS 移植为受控 React 组件，复用真实数据与 API。

**做什么**：
- 全局挂载到 [AppShell.tsx](file:///Users/bytedance/Documents/trae/long_horizon_agent/src/components/layout/AppShell.tsx)（与 `TaskDetailDrawer` 并列，放其前面，保证详情栏 z 更高覆盖在右）。
- `if (!open) return null;`
- 布局：`<aside class="fixed inset-y-0 z-30 flex flex-col border-l bg-white">`，`style={{ width, right: detailOpen ? detailWidth : (assistantOpen ? 400 : 0) }}`。
  - `detailOpen = useTaskDrawerStore(s => Boolean(s.activeTaskId))`。
  - 详情栏宽度：详情栏是 `60vw min 640px`。为对齐，监控栏 `right` 取 `Math.max(window.innerWidth*0.6, 640)`；用一个 resize-aware 的值（`useState` + `window` 监听）或简单用 `min-w` 常量 `640`。**决策：监控栏 right 偏移量 = 详情栏实际宽度**，详情栏宽度固定按 `max(60vw, 640px)` 计算（与 TaskDetailDrawer 一致），用 effect 监听 `resize` 更新。
- **顶部 head**：标题「任务执行情况」+ 收起按钮（`ChevronsRight`，调用 `closeMonitor`）。
- **并发区**：步进器读写 `easterEggSettingsStore`（`getSettings().maxConcurrentTasks` / `updateNumericSetting`），范围 1–10（沿用 config 的 clamp）；占用进度条 = `runningCount / maxConcurrentTasks`，满载变黄（`--paused` 色）。
- **分组列表**：按 `待执行 → 执行中 → 已暂停 → 已完成` 顺序渲染；空板块不渲染；板块头可点击折叠（caret 旋转），状态存 `collapsedSections`。
- **任务卡片**：展示任务名、Goal 名、taskType、triggerRule、状态徽标，底部右侧显示执行时间/完成时间（用 `createdAt` 相对时间；done 用 `result?.completedAt` 或 `createdAt`）。**不展示进度条/百分比**（按用户上一轮要求）。
- **卡片操作按钮**（接入真实逻辑）：
  - `running`：暂停（`runTaskExecutionAction(taskId,"pause",{instanceId})`）、停止（`cancelGoalInstance`）。
  - `queued`：立即开始（`runTaskExecutionAction(taskId,"start")`，达并发上限时禁用并显示「排队中」）、移除（`cancelGoalInstance`）。
  - `paused`：继续（`runTaskExecutionAction(taskId,"resume",{instanceId})`，达上限禁用）、停止。
  - `done`：重新执行（`runTaskExecutionAction(taskId,"rerun")`）。
  - 所有异步操作用 try/catch，失败时用现有的轻提示方式（参考 ConversationView 中 `setStreamError` 模式；本组件用本地 `useState` error + 顶部内联红字条）。Runtime 离线由 `runTaskExecutionAction` 抛错并展示。
- **点击卡片**（非按钮区域）：`useTaskDrawerStore.getState().open(goalId, taskId)` → 复用 `TaskDetailDrawer`。当前选中行高亮（对比 `taskDrawerStore.activeTaskId`）。
- **拖拽宽度**：左边缘加 resizer handle（`absolute left-0 inset-y-0 w-1 cursor-col-resize`），`mousedown` 后监听 `mousemove` 调整 `setWidth`（向左拖变宽，clamp 320–640），移植 demo 的 `makeResizable` 逻辑。
- **收起联动**（effect）：
  - 监控栏 `open` 变 false 时，若详情栏开着则调用 `taskDrawerStore.close()`（直接收监控栏 → 详情栏一并收起）。
  - 详情栏可独立先收（点详情栏自带的关闭按钮，走 `taskDrawerStore.close()`），监控栏保持打开。
- **ESC / 遮罩**：与详情栏一致——按 ESC 时若详情开则先收详情，否则收监控。遮罩点击同理。

### 5. AppShell 挂载与主内容让位：改 `src/components/layout/AppShell.tsx`

**为什么**：抽屉需全局挂载；监控栏为覆盖式（参考现有 TaskDetailDrawer 的覆盖式策略，不挤压主内容），与现有注释「任务侧栏改为覆盖式，不再挤压主内容」一致。

**做什么**：
- import 并在 `<TaskDetailDrawer />` 之前渲染 `<TaskMonitorDrawer />`。
- 路由切换关闭监控栏：在现有 `useEffect(() => { closeTaskDrawer(); }, [pathname])` 同处追加 `useTaskMonitorStore.getState().closeMonitor()`，避免跨页残留。
- 监控栏保持覆盖式（不改 `rightPadding`），与 TaskDetailDrawer 行为一致。

## Assumptions & Decisions

- **并列布局**：详情栏贴最右（复用现有 60vw/right:0 行为，**不改 TaskDetailDrawer**），监控栏置于其左侧（`right = 详情宽度`），监控栏 z-30 < 详情 z-40。（用户已确认）
- **数据范围**：聚合全部 Goal 的全部 TaskInstance；`done` 板块 = 全部历史（completed + error）。（用户已确认）
- **真实逻辑**：开始/继续/暂停/停止/重做接 `runTaskExecutionAction` + `cancelGoalInstance`；并发上限读写 `easterEggSettingsStore.maxConcurrentTasks`。（用户已确认）
- **执行时间展示**：用 `createdAt` 的相对时间（如「2 分钟前」），复用 `@/lib/date` 现有格式化（若无相对时间函数则用简单实现），不展示进度条。
- **不新增后端 API**：仅消费现有 store/lib，不改服务端。
- **入口位置**：仅收件箱页 `page.tsx`（用户原始需求明确为收件箱页）。
