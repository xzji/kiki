KiKi 当前项目整体架构

KiKi 是面向长期目标管理与自主执行的本地 Agent 产品原型。当前架构已经形成“前端投影 + 服务端权威 + 事件回灌 + daemon 执行”的闭环。

前端架构

App Shell

layout.tsx 与 AppShell 负责全局壳层、导航、助手、抽屉和沉浸式页面切换。

领域组件

组件按 conversation、goal、task、execution、inbox、schedule、settings 分域，避免页面级巨石继续膨胀。

Runtime Bridge

RuntimeEventBridge 常驻浏览器，消费 SSE / snapshot 并替换 store 投影。

Store 分工

Store当前职责
goalStore.tsgoals snapshot 投影、实例状态 / progress / notification 回灌、optimistic overlay 合成。
conversationStore.ts会话列表、消息、目标信息收集状态、Claude session 与 runtime env 关联。
assistantStore.ts右侧助手消息流、发送态、中断与权限请求。
runtimeEnvStore.ts本地运行环境列表、默认环境和健康状态。
inboxStore.ts / scheduleStore.ts收件箱和日程事件的前端投影。
关键变化： canonical goals 不再由浏览器本地持久化。用户操作只写 pending overlay，并通过命令 API 等待服务端确认。

服务端权威模型

当前核心不变量是：服务端是 Goal 与运行态事实源，浏览器只负责提交命令和展示投影。

用户操作
  • 组件写入 pending overlay，界面立即显示“保存中”。
  • 提交 command + Idempotency-Key + baseRevision 到 /api/goals/commands。
服务端命令
  • goalCommandService 校验结构、幂等键和 revision。
  • 先 append goal_event_log，再写 runtime_state_snapshots.goals。
事件回灌
  • SSE 推送 goal events，snapshot API 提供兜底全量投影。
  • RuntimeEventBridge 更新 goalStore 并清理已确认 overlay。

Daemon / Worker

本地运行时入口是 pnpm daemon / pnpm worker，最终进入 runRuntimeDaemonLoop()。

每轮循环

读取 runtime env 与 goals snapshot，运行 scheduler，执行通知与 watchdog，派发 queued job，写入 heartbeat 与日志。

浏览器职责

浏览器不再负责调度、通知或 watchdog，只消费 daemon / worker 产生的事件和 snapshot。

Worker职责
goalSchedulerEngine.ts判断触发规则，通过 startTaskAttempt 创建实例与 runtime job。
taskDispatchWorker.ts消费 runtime job，执行任务，更新 progress、result 和 blocker。
goalNotificationWorker.ts通知投递、日程合成、超时暂停。
recoveryWorker.ts异常恢复和运行态收敛。

API 与执行链路

主要 API 面

  • /api/goals/commands：Goal 结构变更命令面。
  • /api/goals/events：goal event 增量查询与 SSE。
  • /api/runtime/state：runtime snapshot 查询与同步。
  • /api/goals/instances/*：实例取消、响应、迁移和 runtime 查询。
  • /api/goals/clarify|collect|plan：目标澄清、信息收集和规划。
  • /api/artifacts/*：产物读取、预览和交互状态。

任务执行链路

Scheduler / 用户手动启动
  -> startTaskAttempt
  -> enqueueGoalRuntimeJob
  -> taskDispatchWorker
  -> goalTaskRunner / helpers
  -> Claude transport
  -> goalRuntimeService
  -> RuntimeEventBridge

src/lib/server/claude/transport.ts 是 Claude CLI 单入口，对外提供 runPromptJson 与 streamPrompt，负责 CLI 路径、环境变量、cwd、权限模式、abort signal 和 stdin prompt 传输。

架构约束

  • 服务端权威：canonical goals 只能来自服务端 snapshot。
  • 单点命令：Goal 结构变更必须通过 goalCommandService。
  • 单点写入：运行时写入集中到 goalRuntimeService。
  • 幂等键：状态变更命令必须带 Idempotency-Key。
  • Revision 冲突：覆盖结构命令必须传 baseRevision。
  • Overlay 隔离：pending 状态不能写入 canonical goals。
  • SSE cursor：维护 lastGoalEventId 支持断线续传和多 tab。
  • 浏览器不调度：调度、通知、watchdog 由 daemon / worker 负责。
  • Claude 单入口：CLI 调用统一走 claude/transport.ts。
  • 领域规则集中：任务确认、交互需求、错误分类集中到 taskPolicy.ts。
  • 运行态隔离：data/*.db、*.db-shm、*.db-wal 不提交。
