托管智能体如何扩展：把“大脑”和“手”拆开

这篇文章的核心不是某个新工具，而是一种面向未来模型的系统设计：不要把 Claude、运行循环、执行环境和会话历史绑死在一个容器里，而是把它们抽象成可替换、可恢复、可扩展的接口。

一句话讲清楚

Managed Agents 是一个“元 harness”：它不押注某一种固定的 agent 实现，而是押注一组稳定接口，让未来的模型、工具、沙箱和上下文工程都能替换。

为什么要拆

旧做法把所有东西塞进一个容器：会话记录、调用 Claude 的 harness、执行代码的 sandbox。短期简单，长期会变成一只必须细心照料的“宠物服务器”。

可靠性

容器成了“宠物”

如果容器不响应，工程师必须照料它；如果容器失败，session、执行状态和调试线索可能一起消失。

可观测性

故障来源混在一起

harness bug、网络包丢失、容器离线都可能表现成同一种失败，系统很难安全地进入容器排查。

可扩展性

位置假设被写死

harness 默认 Claude 要处理的资源就在本地容器里，一旦客户资源在自己的 VPC 或其他环境中，架构就变得笨重。

新抽象：脑、手、会话

Anthropic 把 agent 虚拟化为三个组件。关键点是：它们通过接口协作，而不是共享同一个脆弱运行环境。

Session

可恢复的事件日志

它不是 Claude 的上下文窗口，而是持久化、可查询、可切片的外部上下文对象。

Harness

无状态的运行循环

它负责调用 Claude、路由工具调用、写入事件；失败后可以通过 session log 重新唤醒。

Sandbox

可替换的执行环境

容器、MCP、自定义工具、远端资源都可以被看作“手”，统一暴露执行接口。

几个接口决定架构性格

文章反复强调：真正稳定的是接口，而不是今天的 harness 实现。接口越少、边界越清楚，底层实现越能自由演进。

execute(name, input) -> string provision({ resources }) wake(sessionId) getSession(id) emitEvent(id, event) getEvents()

先接收任务

orchestration layer 从 session log 中拉取待处理事件，harness 不需要等待容器启动。

再启动推理

brain 先生成响应或计划；如果暂时不需要 sandbox，就不付容器冷启动成本。

按需调用工具

需要执行时，通过统一的 execute 接口把工作交给某个“手”。

失败可恢复

容器失败就是工具错误；harness 失败则重新 wake，并从 durable session 续跑。

Session 不等于上下文窗口

长任务会超出模型上下文窗口。压缩、裁剪、记忆文件都要决定“保留什么、丢弃什么”，而这些决定可能在未来变成错误。Managed Agents 的做法是把原始事件放在上下文窗口外。

上下文窗口内

  • -容量有限，长任务必然遇到窗口压力。
  • -压缩和裁剪会做不可逆选择，未来可能需要被丢弃的细节。
  • -harness 需要决定如何组织上下文以提高 prompt cache 命中率。

Session log 中

  • +事件持久保存，brain 可以按位置切片、回看、重读。
  • +原始上下文可恢复，具体整理策略留给 harness 演进。
  • +将“可恢复存储”和“上下文管理策略”拆开。

安全边界：凭证不进沙箱

旧架构中，Claude 生成的不可信代码和凭证在同一个容器里；提示注入只要诱导 Claude 读取环境变量，就可能拿到 token。结构性修复是让凭证永远不对 sandbox 可达。

Git 资源

凭证绑定到资源初始化

仓库访问 token 用于初始化 clone，并被接入本地 remote。sandbox 中可以 push/pull，但 agent 不直接持有 token。

MCP / OAuth

凭证放在外部 vault

Claude 调 MCP 工具时经过专用 proxy；proxy 用 session 关联 token 去 vault 取凭证，harness 本身也不知道凭证。

许多大脑，许多双手

解耦之后，扩展不再等于“每个 brain 都先启动一个完整容器”。harness 可以无状态扩容，执行环境按需连接。

60% p50 TTFT 约降低 60%。用户更快看到第一个响应 token。
90%+ p95 TTFT 降低超过 90%。尾部延迟改善最明显。
Many brains

启动更多无状态 harness

推理可以在拉取 session 事件后立即开始；只有需要执行时才 provision sandbox。

Many hands

一个 brain 可连接多个执行环境

harness 不关心“手”是容器、手机、MCP server 还是模拟器；统一把它当成可调用工具。

这篇文章真正想表达什么

01

不要把当前模型缺陷写死进架构

harness 经常是在弥补模型暂时做不到的事；模型变强后，这些假设会过期。

02

接口比实现更长寿

像操作系统抽象文件和进程一样，Managed Agents 抽象 session、harness、sandbox。

03

可靠性来自可替换

容器和 harness 都应是 cattle，坏了就替换，而不是进入脆弱环境手动救火。

04

安全性来自结构隔离

不要只依赖 token scope；更根本的是让不可信代码根本够不到凭证。

05

长任务需要外部记忆对象

session log 把可恢复上下文放到窗口外，让 harness 自由选择未来的上下文工程策略。

06

智能提升会改变系统边界

早期模型需要单容器降低认知负担；更强模型能管理多环境，旧边界反而成为瓶颈。
